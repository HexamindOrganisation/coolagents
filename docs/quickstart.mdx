---
title: "Quickstart"
description: "Install hexgate and watch a role + arguments decide a tool call — no API keys."
---

<Steps>
  <Step title="Install the package">
    ```bash
    pip install hexgate
    ```

    Or, for a local checkout:

    ```bash
    git clone https://github.com/HexamindOrganisation/hexgate.git
    cd hexgate
    pip install -e .
    ```
  </Step>

  <Step title="See it enforce — no API keys needed">
    Save this policy as `policy.yaml`. It gives two roles different limits on the
    **same** `refund_order` tool:

    ```yaml
    version: 1
    roles:
      support:                       # front-line: small USD refunds only
        default_policy: { mode: deny }
        tools:
          refund_order:
            mode: allow
            constraints:
              - args.amount <= 50
              - args.currency == "USD"
      billing:                       # larger refunds, major currencies
        default_policy: { mode: deny }
        tools:
          refund_order:
            mode: allow
            constraints:
              - args.amount <= 500
              - args.currency in ["USD", "EUR"]
    ```

    Now ask Hexgate to decide the **same $400 refund** for each role. `hexgate
    policy test` evaluates a policy offline — no model, no API keys:

    ```bash
    hexgate policy test policy.yaml --role support \
        --tool refund_order --args '{"amount": 400, "currency": "USD"}'
    # ✗ DENY · support → refund_order({"amount": 400, "currency": "USD"})
    #   reason: Policy on "refund_order" denied: constraint failed — args.amount <= 50

    hexgate policy test policy.yaml --role billing \
        --tool refund_order --args '{"amount": 400, "currency": "EUR"}'
    # ✓ ALLOW · billing → refund_order({"amount": 400, "currency": "EUR"})
    ```

    Same tool, same request — **the caller's role and the arguments decide.** That
    is the whole idea. The limits live in the policy, outside the model, so a
    confused or prompt-injected agent can't raise its own cap. See
    [policy YAML shape](/policy/yaml-shape) and [constraints](/policy/constraints)
    for the full grammar.
  </Step>

  <Step title="Set up environment variables">
    To run a live agent (next step), copy the sample env and fill in the keys the
    example agent uses:

    ```bash
    cp .env.sample .env
    ```

    ```bash
    OPENAI_API_KEY=sk-...     # the default model
    LINKUP_API_KEY=...        # the built-in web_search tool
    TAVILY_API_KEY=...        # the built-in fetch tool
    ```

    None are required to boot — each is only read when you invoke the piece that
    uses it. See the [environment reference](/reference/environment).
  </Step>

  <Step title="Run the chat REPL">
    ```bash
    hexgate chat --agent example_agent
    ```

    A single-process REPL with policy decisions rendered inline — denies and
    approval-required calls show up as panels in the terminal. `hexgate chat` sets
    `HEXGATE_LOCAL_MODE=1` automatically, so audit stays on your machine.

    <Note>
    The bundled `example_agent` uses a deliberately permissive policy (it just
    allows `web_search` + `fetch`) so the first run is friction-free. To watch
    role-based enforcement in a live agent, attach a role-aware policy with
    [`HEXGATE_LOCAL_POLICY`](/policy/local-override) and run under a
    [`User` scope](/concepts/user-scope), or explore the vertical examples in
    `examples/` (`demo_policy.yaml`, `healthcare_policy.yaml`, `hr_policy.yaml`).
    </Note>
  </Step>
</Steps>
